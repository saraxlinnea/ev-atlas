# AGENTS.md

Instructions for AI coding agents (Cursor, Claude Code, etc.) working in this
repo. Human-facing docs are `README.md` and `docs/METHODOLOGY.md`.

EV Atlas compares EVs by spec market (mostly US today; CN is opt-in). Every
number has to be traceable to a source. Follow these rules even when it's
slower.

## Branding

```

```

Site UI follows that preset only. Do not blend with other design presets.

## Site voice

Site HTML and meta descriptions use third person only (no I/me/my/we/our).
Register: compressed scientific Methods + calm science-interactive prose.
Blank/— means not found, not zero; not a ranking; do not claim full OEM coverage.
Chart notes read as figure legends; keep wall-side vs battery-side distinct.
No slogans, banned AI filler, or em dashes in prose. Rephrase limitations for
register only; never invent or soften them.

## Where things live

- `claims/<vehicle_id>.json`: list of claim objects. The source of truth.
- `data/vehicles.json`: vehicle identity only (make, model, trim, model_year,
  `region`). No specs. `region` is the **spec market** (US or CN), not brand
  HQ or factory country. US-sold and China-market variants of the same badge
  are different `vehicle_id` rows.
- `data/*.csv`: generated by `flatten.py`. Never edit by hand.
- `schema/claim.schema.json`, `schema/vehicle.schema.json`: JSON Schemas.
- `schema/vehicle-fields.md`: every allowed field, its unit, and its typical tier.
- `charts/`: Vega-Lite specs that read only from `data/*.csv` (source specs; data URL is `../data/...`).
- `site/`: static preview. Hand-edit `index.html`, `compare.html`, `figures.html`,
  `methodology.html`, and `style.css` only. `charts.html` redirects to `figures.html`.
 `build_site.py` copies chart CSVs/specs into `site/data/` and `site/charts/`, and
 writes `site/data/compare.json` from `data/flattened.csv` (winning values for the
 compare table) plus `conflicts` / `conflict_alts` from `claims/` for progressive
 disclosure on Compare. Those generated paths are gitignored.
- `private/`: gitignored. Anything proprietary or personal goes here, never elsewhere.

## Hard rules

1. **No bare numbers.** A spec value (kWh, kW, mph, lb, $, ...) never goes
   directly into a chart, CSV, table, or prose. It must first exist as a claim
   in `claims/`, and everything downstream reads `data/flattened.csv`.
2. **Never invent a `source_url`.** Tier P and S claims need the URL of the
   page you actually opened and saw the value on. If you don't have one, use
   tier `unverified` and omit `source_url`. Don't reconstruct URLs from memory,
   and don't cite a bare domain (`https://example.com/`).
3. **Don't fill gaps.** If a field isn't disclosed anywhere you can find,
   leave it absent. Missing data shows up in the disclosure heatmap; a guessed
   number is worse than a gap.
4. **Record disagreements; don't resolve them.** When sources disagree, add
   both claims on the same `field`, each with `conflicts_with` pointing at the
   other (`vehicle_id#field#source_name`). `flatten.py` picks the higher tier
   (then higher confidence on a tie) and flags the conflict. Don't delete the
   losing claim.
5. **Derived claims (tier D)** need `derivation.formula` and
   `derivation.inputs`, and every input must resolve to an existing claim.
6. **Validation blocks commits.** Don't get around a failure by loosening the
   schema or the validator.
7. **No proprietary data.** Nothing from paid teardown databases,
   subscription reports, or other proprietary sources. If you're unsure where
   a number came from, leave it out and note the gap.

## Writing claims

- Required: `vehicle_id`, `field`, `value`, `tier`, `access_date` (ISO date
  you checked the source). P/S also need `source_name` and `source_url`.
- Tiers: **P** = OEM page/press release, EPA, NHTSA, other government source.
  **S** = outlet, teardown, aggregator. **D** = computed from other claims.
  **unverified** = plausible but no findable source.
- `source_name` describes the specific page, e.g. "Lucid Group press release,
  2025-07-22: 2026 Lucid Air lineup", not "OEM website".
- If the value's unit differs from the field default in `vehicle-fields.md`,
  set `unit` (e.g. `"unit": "Nm"` on `powertrain.torque_lbft`). Never convert
  silently.
- If the source is for a different model year than the vehicle, set
  `model_year` on the claim and lower `confidence`.
- `notes` hold caveats and provenance in plain language. No process chatter
  ("this session", "found via search"). If a figure couldn't be re-found,
  say that.
- `battery.pack_kwh` always needs a `battery.pack_kwh_basis` claim
  (gross/usable/unstated).
- `efficiency.epa_kwh_per_100mi` is wall-side (includes charging losses);
  `derived.kwh_per_100mi_battery_side` is battery-side. Never relabel one as
  the other.
- Never put CLTC values into `efficiency.epa_*`. Never invent CLTC↔EPA or
  CNY→USD conversions. China prices use `identity.msrp_cny` or stay blank.
  Leave NHTSA recall fields absent on China-only rows (blank ≠ zero).
- `model_year` (on the vehicle) and `lineage_id` (groups generations) are
  different things. Don't collapse them.

## Adding fields or vehicles

- **New field:** add a row to `schema/vehicle-fields.md` and, if it belongs in
  the heatmap, to `TRACKED_FIELDS` in `scripts/flatten.py`. The validator warns
  on undocumented fields.
- **New vehicle:** add it to `data/vehicles.json` (status
  `unverified_availability` until confirmed; set `region` to `US` or `CN`)
  and create `claims/<vehicle_id>.json` containing `[]`. Use the model year
  the vehicle is actually sold as. For US rows, check EPA and NHTSA first.
  For CN rows, prefer OEM or MIIT pages actually opened (tier P); aggregators
  are tier S. Leave EPA and NHTSA fields absent on China-only rows.
- **Trims:** use the entry-level EPA configuration unless told otherwise. When
  EPA lists wheel or charger variants, say which you picked and why in the
  claim notes.

## Source quirks

**EPA (fueleconomy.gov)**
- Per-vehicle record: `https://www.fueleconomy.gov/ws/rest/vehicle/<id>` (XML).
  Cite this URL and put the EPA id in notes.
- Bulk data: `https://www.fueleconomy.gov/feg/epadata/vehicles.csv.zip`. Useful
  for finding ids; filter `atvType == "EV"`.
- Fields: `range` → `efficiency.epa_range_mi`, `combE` →
  `efficiency.epa_kwh_per_100mi` (the label rounds it), `comb08` →
  `efficiency.epa_mpge_combined`, `drive` → `powertrain.drive_layout`,
  `evMotor` → `powertrain.epa_motor_description` (verbatim; don't parse it into
  motor counts).
- EPA's model names don't always match the OEM's trim names. Confirm the
  mapping from the OEM page (for example, Tesla's "Premium RWD" is EPA's
  "Model Y Long Range RWD").

**NHTSA recalls**
- `https://api.nhtsa.gov/recalls/recallsByVehicle?make=...&model=...&modelYear=...`
  Use the bare model name (`AIR`, `MODEL Y`, `BOLT EV`), without the `BEV` suffix
  that the products endpoint shows.
- HTTP 400 with `Count: 0` means the model string didn't match, **not** zero
  recalls. Confirm zeros against the flat file:
  `https://static.nhtsa.gov/odi/ffdd/rcl/FLAT_RCL_POST_2010.zip` (tab-delimited;
  field list at `https://static.nhtsa.gov/odi/ffdd/rcl/RCL.txt`).
- The products endpoint (`/products/vehicle/models?...&issueType=r`) sometimes
  lists models with no actual campaigns. Where it contradicts the campaign
  count, record both as a conflict.
- Fields: `recalls.campaign_count`, one `recalls.campaign_<id>` per campaign
  (id without the trailing `000`), and `recalls.listed_as_having_recalls` only
  for the contradiction above. Queries are by make/model/year, not trim.

**OEM sites**
- Tesla blocks scripted requests (403). Read it in a real browser. The Model Y
  page defaults to the base trim; switch to the right trim's spec tab.
- Lucid's live site moves to the next model year early. For older years, use
  Lucid's investor-relations press releases or a Wayback Machine snapshot of
  the Lucid page (cite the `web.archive.org` URL; it's still tier P).
- EV Database (ev-database.org) lists European-market variants (Type 2 port,
  different AC rates). Treat it as tier S, low confidence, and say it's an EU
  listing.

## Done means

- `python scripts/validate.py` passes with no warnings you introduced.
- `python scripts/flatten.py` has been re-run and the regenerated CSVs are

  `docs/METHODOLOGY.md` and the Status section in `README.md`.
